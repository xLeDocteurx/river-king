# Plan — Undo/Redo in scene/sprite/tile editors (issue #1)

Date: 2026-08-29 · Branch: `feature-1` · Kanban: Backlog → Ready → In progress ✅

## Contexte

Les éditeurs (scene, sprite, tile) ne permettent pas d'annuler les actions. Un stub
`UndoService` (core/services/undo.service.ts) existe déjà : pile partagée, root-provided,
`push/undo/redo/clear` + signaux `canUndo/canRedo/undoLabel/redoLabel`, `MAX_STACK_SIZE=100`.
Le scene-editor l'utilise déjà pour le placement de tuiles (auto-grow).

## Scope

### Global

1. **Raccourcis clavier** — nouveau `core/services/keyboard-shortcuts.service.ts` (root) :
   `Ctrl/Cmd+Z` = undo, `Ctrl/Cmd+Shift+Z` = redo, écouté sur `document`; ignoré quand le focus
   est dans un champ éditable (`input/textarea/select/contenteditable`).
2. **Vidage de la pile au changement de projet** — dans `app.ts` (racine) : `effect` suivant le
   signal `projectId` existant → `undo.clear()`.

### Scene editor (scene-editor.component.ts)

- Placement de tuile : déjà couvert (auto-grow).
- **Suppression de scène** (`onConfirmDelete`) : capture la ligne `Scene` avant suppression;
  undo = `sceneService.restoreScene(scene)` + `loadScenes()`; redo = `deleteScene` à nouveau.
  → ajouter `restoreScene(scene: Scene): Promise<void>` à `SceneService`.
- **Opérations de layer** (add / delete / toggle visible / opacity / rename / reorder) : undo
  générique capturant `previousLayers`/`newLayers` (deep copy) ; closures `updateScene` +
  mise à jour du signal `selectedScene`.
- **Déplacement de scène** (`onSceneFolderChange`) : capture l'ancien `folderPath`.

### Sprite editor (sprite-editor.component.ts)

- **Trait (stroke)** : déjà couvert — mais colmater le gap de persistance : les closures
  `execute/undo` écrivent aussi en DB (`spriteService.updateSprite` avec `paletteIndices` +
  `pixelData`).
- **Frames** (`onAddFrame`/`onDeleteFrame`/`onDuplicateFrame`/`onFrameReorder`/
  `onUpdateTileType`/`onUpdateAnimationSpeed`) : pour chaque op, push action capturant les états
  avant/après (`spriteIds`, `type`, `animationSpeed`, ligne sprite supprimée le cas échéant) ;
  closures persistant via `tileService.updateTile` + `spriteService`. → ajouter
  `restoreSprite(sprite: Sprite): Promise<void>` à `SpriteService` (pour le undo d'un frame
  supprimé).

### Tile manager (tile-manager.component.ts)

- **Création de tuile** (`createTile`) : capture tuile + premier frame; undo = `deleteTile`;
  redo = restauration des 2 lignes.
- **Suppression de tuile** (`deleteTile`) : capture tuile + sprites liés AVANT suppression;
  undo = restauration ; redo = re-suppression.
- **Édition / rename** (`saveTile`) : capture l'ancienne ligne; undo/redo = `updateTile`.
- **Déplacement de tuile** (`onTileFolderChange`) : capture l'ancien chemin.
- **Déplacement de dossier** (`onFolderMove`) : capture les triplets `{tileId, oldPath, newPath}`.
- **Création de dossier local** (`onCreateFolder`, local signal only) : undo = retrait du signal.
  → ajouter `restoreTile(tile: Tile, sprites: Sprite[]): Promise<void>` + accesseur sprites à
  `TileService`.

### Hors scope (documenté dans le PR)

- État purement UI non persistant (folders collapsed, onion skin, sélection d'outil/couleur).
- Palette au niveau projet (dashboard).
